## 4. Pairwise word scan (phase 2b)

A `name word` is `PREFIX-SYLLABLE + SUFFIX-SYLLABLE` (8 letters). Bad text or
awkward clusters that cannot exist inside an individual clean token CAN still
form at the join (`P[3]+S[0]`). So every pair of every candidate `A × B` pool
combination was scanned (screen: `scripts/data/scans/`).

`offensive` = profane substring/word spanning the join; `awkward` = banned/doubled
consonant proportion at the join (pronounceability, not offense).

Plain-English reading of §4:
- **Vowel-final prefixes (CVCV) never create an awkward boundary** (0) and keep
  offensive spans to ≤0.7% of all words.
- **Consonant-final prefixes (CVCC / CVVC / CCVC)** create millions of awkward
  join clusters (doubled letters like `-bb-`, awkward pairs) — they would
  need aggressive per-pair pruning to be usable as the prefix slot.
- A fully-clean guarantee (0 offensive words across ALL names) is achievable by
  pruning tokens whose edge letters can complete a banned 3-letter substring
  with the other pool — the scan provides the exact bad-pair data to drive that.

## 5. Feasibility & capacity (the 1024 / 2048 / more question)

The encoding maps each syllable slot to a fixed number of **bits**: with `1024`
tokens per pool a slot needs 10 bits; the current wire format is exactly 5 bytes
= 40 bits = 2×20-bit words = **2^40 ≈ 1.1 trillion** names. Going larger:
| slots/list (2^b) | bits per word | wire bytes | total names                  |
|------------------|---------------|------------|------------------------------|
| 512 (b=9)        | 18            | 5          | 2^36 ≈ 68,719,476,736        |
| 1,024 (b=10)     | 20            | 5          | 2^40 ≈ 1,099,511,627,776     |
| 2,048 (b=11)     | 22            | 6          | 2^44 ≈ 17,592,186,044,416    |
| 4,096 (b=12)     | 24            | 6          | 2^48 ≈ 281,474,976,710,656   |
| 8,192 (b=13)     | 26            | 7          | 2^52 ≈ 4,503,599,627,370,496 |

> Each doubling of the list size multiplies the name space by 4. Beyond the
> 1024-per-pool (10-bit) scheme the wire format, `MASK_40`, the Feistel word
> width, the 9×9 avatar, and the LMDB key all change — that is a **breaking**
> protocol upgrade, intentionally out of scope here.

## 6. Recommendations

- **CVCV stays the pool to ship.** It is vowel-final on both slots, ~7175 clean
  tokens, zero awkward joins, and comfortably feeds a 4096-per-pool slot.
  That is **2^48 ≈ 281 trillion** names with a 6-byte wire upgrade, or 2^40
  with today's 5-byte format.
- CVVC (7224) and CVCC (2191) add consonant-final flavor but land in the prefix
  slot badly (→ §4). CVCC is viable only as the *suffix* slot,
  giving consonant-final words; the join stays vowel→consonant and clean.
- Treat `rules.json`'s profanity list as a thin starter: expand it, review it, and
  run the pairwise scan again before anything ships.

## 7. Final curated lists (`select.py`, slot 4096)

Greedy pipeline: remove tokens that cause offensive *joins* (approximate minimum
vertex cover of the bad-word graph), assign survivors to prefix/suffix slots
minimizing 1-letter lookalikes, then borrow across slots to reach 4096 each.

- Clean pool after join-prune: **6,154** tokens (now 0 offensive words across the whole 4096×4096 = 16.8M word table — verified 0).
- Prefix list 4,096 tokens, 49,571 1-letter-lookalike pairs; suffix 49,731.
- Shared tokens 2,038 → reduplication inside a word ~1 in 8,232.
- Estimated first 1-letter-twin name: ~3,407,382 ordinal (current 1024-scheme: ~265k → ~13× better).
  Name space at 4096/slot: **2^48 ≈ 281,474,976,710,656** names.

Sample: `python3 scripts/curate/sample.py --count 100 --seed 1`
